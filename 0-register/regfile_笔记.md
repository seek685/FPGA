# 寄存器堆 regfile 笔记（2026-07-28）

## 一、作用

- CPU 中存放 32 个通用寄存器（x0~x31）的模块，指令的操作数来源和结果归宿
- RISC-V 规定 x0 恒为 0

## 二、实现要点

- 存储：`reg [31:0] regs[31:0]`。端口只是接口（电线，无状态），数组才是真存储；地址 = 数组下标（5 位覆盖 0~31）
- 写（时序逻辑）：`always @(posedge clk)`，`we=1` 且上升沿才 `regs[waddr]<=wdata`，平时保持
- 读（组合逻辑）：`assign` 连续赋值，写在 always 块外；地址变数据立即变，不等沿
- 两个读口相互独立：一条指令同一拍要读 rs1、rs2 两个源寄存器
- x0 保护放读侧：`assign rdata1 = (raddr1==5'd0) ? 32'd0 : regs[raddr1];`
  只靠写侧禁止不行——仿真上电格子是 x，读出不是 0

### 读写行为（对照硬件理解）

模块内部是一个"数组"：32 个格子，每个 32 位。想成一栋 32 层小楼，门牌号 0～31。读和写是两条完全独立的通路，各管各的。

**写通路：看时钟行事（时序逻辑）**

- 平时什么都不做，格子里的值原样保持
- 只有时钟上升沿到来的一瞬间，才检查写使能 we：
  - we=1：把 wdata 抄进门牌号为 waddr 的格子，边沿过后新值生效
  - we=0：什么都不发生，waddr/wdata 乱动也无视
- 关键：写入是"边沿触发"。两个上升沿之间摆好 we/waddr/wdata，等下一个沿"盖章"，不是 we 一变高就立刻写

**读通路：不看时钟（组合逻辑）**

- 跟时钟毫无关系，时刻都在工作
- 任何时刻，rdata1 就是门牌号 raddr1 那个格子当前的内容（rdata2 同理）
- 本质是 32 选 1 选择器：地址是选择信号，数据是被选中的那一路
- 地址一变，数据经组合逻辑延迟后立即跟着变，不等任何时钟沿
- 两个读口 = 两套选择器，同时工作互不干扰（一条指令同拍读 rs1、rs2）

**x0 的处理**

- "读 x0 永远得 0"放在读通路：地址是 0 就直接出常数 0，根本不去读格子
- 为什么不能只靠"写时禁止写 0 号格子"：仿真上电格子是未知态 x，没人写过 0 号格子的话读出来是 x 不是 0。读侧强制出 0，格子里是什么都无所谓


   ```
                      regfile 模块（一个 .v 文件）
             ┌─────────────────────────────────────┐
       clk ──┼──►                                  │
       we  ──┼──►   写控制                          │
     waddr ──┼──►  (按门牌号选格子)      ┌─────────┐ │
     wdata ──┼──►──────────写入────────► │ regs[0]  │ │
             │                           │ regs[1]  │ │ ← 这 32 个格子才是
     raddr1 ─┼──►  读选择器1 ──┐          │   ...    │ │   真正的存储（触发器）
     raddr2 ─┼──►  读选择器2 ──┤          │ regs[31] │ │
             │                 │          └─────────┘ │
     rdata1 ◄┼─────────────────┘  从被选中的格子读出     │
     rdata2 ◄┼─────────────────┘                      │
             └─────────────────────────────────────┘
   ```

   • 边界上的端口（clk/we/waddr/wdata/raddr/rdata）：只是电线，没有任何存储能力。外部给什么值，它就是什么值，像快递柜的
     操作面板——面板不是柜子。                                                                                         
   • 内部的 32 个寄存器：才是真正的存储，每个 32 位触发器组，值会一直保持到下次被写。

## 三、regfile.v 犯过的错

- `assign` 写进 always 块：`assign` 只在块外，always 内直接赋值

## 四、tb 犯过的错（重点）

1. **结构错位**：信号声明写到 module 外；激励语句、例化、预置写到模块级或 initial 外；always 塞进 initial 里
   → 规则：结构（声明/例化/时钟）归模块级，动作（赋值/延时/检查）归 initial
2. **tb 自己声明 regs 数组**：寄存器在 DUT 内部，预置用层次引用 `u_regfile.regs[2]=...`（tb 专用，不可综合）
3. **例化用 `{}`**：改圆括号 + 分号
4. **clk 没初始化**：`~x = x`，时钟永远是 x → `initial clk=0;`
5. **wdata 声明成 wire**：tb 要驱动它 → DUT 输入用 reg，输出接 wire
6. **时序竞争**：`@(posedge clk)` 后立刻 `we=0`，tb 和 DUT 同沿抢，写入可能丢 → 沿后加 `#1`
   → 节奏口诀：下降沿摆信号 → 上升沿盖章 → #1 再读、再收 we
7. **期望值写反**：x0 写保护测试期望 `0xFFFF_FFFF` → 应期望 0（期望值来自规格，不是直觉）
8. **x5"旧值"无来源**：没写过就读 → 先写后读
9. 小错：`$diplay`→`$display`；`error`→`errors`；`raadr2`→`raddr2`；`$finish` 缺分号；tb 激励用 `=` 不用 `<=`

## 五、自检方法论

- 自检 = tb 自己比对"实际输出 vs 期望值"，打 PASS/FAIL，errors 计数，结尾汇总
- 比较用 `!==`（x/z 也算错）
- 验收 tb：故意改错 DUT，tb 必须能打出 FAIL——能抓错的 tb 才是好 tb

## 七、离"比赛能用"还差什么

- 功能规格已满足单周期 RV32I 核的要求（2 读 1 写 + x0 保护），**不需要重写**
- 差的是三层验证：
  1. 仿真 ALL PASS（今天闭环）
  2. 综合 + 远程平台上板（第 4 周）
  3. 装进 CPU 后联调（第 2~3 周）
- 留给流水线核的问题：同周期写读同地址，读到新值还是旧值？
  本设计的答案 = 沿后读到新值（写在沿、读是组合）
